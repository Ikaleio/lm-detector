`data/` 保存正式参考样本、派生指纹库、冻结检测参数、固定采样挑战和分词器探测用的分词器库。

```files
data
├── unified_reference.jsonl
├── unified_bank.json
├── shared_detector.json
├── enrollment-suite.json
├── tokenizer_bank.json
├── import_manifest.json
└── collections
```

| 文件 | 内容 |
| --- | --- |
| `unified_reference.jsonl` | 参考批次，每行一个版本 1 批次：共用模型、渠道与调用设置，回答放在 `samples` 数组中 |
| `unified_bank.json` | 由参考批次派生的统计库 |
| `shared_detector.json` | 冻结的排名器和校准参数，用 SHA-256 绑定参考数据 |
| `enrollment-suite.json` | 36 道固定采样挑战；它是采样输入，不是参考回答 |
| `tokenizer_bank.json` | 分词器库：分词器探测用的测试文本、每一类分词器的计数和型号映射 |
| `import_manifest.json` | 历史清单，不代表当前数量 |
| `collections/` | 采样请求、尝试和来源核验记录 |

`collections/` 不参与评分，也不复制到网站的公开数据。改名、退库或迁移格式前的参考行不再另存副本，需要时从 git 历史找回。批次与样本的字段见[采样与续采](../cli/sampling.mdx#batch-format)。

## 维护规则

- `fpd sample`、`fpd enroll DIR` 和 `fpd retrain --data-dir DIR` 都可以在仓库外运行。入库校验完整批次和原始证据，按模型、渠道、条件、题目与文本去重并重建派生库；重训从目标参考库离线拟合排名器与置信度校准，嵌套校准未通过时不替换 `shared_detector.json`，训练证据保存在 `.training/`。
- CLI 随包数据只读；维护目标必须显式指定，或在交互入库时识别本仓库后确认。
- 固定评估集不能加入参考库、模型中心或校准。
- 网站构建把脱敏数据写入 `web/public/data/`。该目录是生成产物，不能作为另一份正式库维护。构建同时从参考批次的 `usage` 派生 `usage_fit.json`：每个至少有 8 条带用量回复的模型一行用量拟合，供网页的[用量比对](../web/index.mdx#usage-check)使用。

## 分词器库

`tokenizer_bank.json` 由分词器归档工具 llm-tokenizer-fingerprint 的 `token-fp export-api-bank` 从 290 个开源分词器离线生成。它与参考样本无关，更新时直接整体替换，不经过 `fpd enroll`。

| 字段 | 内容 |
| --- | --- |
| `schema` | 固定为 `tokenizer-bank-v1` |
| `source` | 生成工具、分词器数与候选文本数；`archive_manifest_sha256` 记录所用归档清单的哈希，`excluded` 列出因归档文件不可信而未导出的仓库及原因 |
| `wrapper` | 固定前后缀：`prefix` 与 `suffix` |
| `probes` | 测试文本的 ID、类别与原文 |
| `classes` | 每一类分词器的实验室、系列、成员、别名，以及对每条测试文本的计数差 `counts`；成员分歧时另列 `alternatives` |
| `api_models` | 厂商型号到分词器类的映射；`class` 为 `null` 表示厂商没有公开分词器 |

类按作者实验室与系列归并：计数完全相同的分词器归为一类，同一谱系下只差少数文本的再合并。完整的类列表见[分词器探测原理](../principles/tokenizer.mdx#classes)。
